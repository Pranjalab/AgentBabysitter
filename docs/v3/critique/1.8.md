# Critique — Step 1.8: Phase-1 hardening + docs (and the Phase-1 retrospective)

The last Phase-1 step: crash/restart recovery, real log rotation, the reboot

## What was built (1.8)

- **Crash/restart recovery** (`Poller.boot_recover_and_notify`, run once per boot).
  On startup the daemon re-derives full state from disk instead of starting blank:

  | `daemon-handoff.json` | recorded pane/pid | `session.pid` | → resulting state |
  |---|---|---|---|
  | present | pane OR pid **alive** | any | **SESSION_LIVE** — resumed with FIX B/C precision (recorded `pane_id` + `launcher_pid` + `chat_id`); `lived_s` derived from the marker timestamp |
  | present | **dead** | any | **RECLAIM → IDLE** — kill engine leftover, emit `session_end`/`reclaim_done`, clear marker, send the reboot notice |
  | absent | — | **live** | **IDLE** — a terminal session; yield (existing behavior) |
  | absent | — | **stale** (dead) | **IDLE** + reboot notice (to the profile's rc.json chat) |
  | absent | — | none | **IDLE** — poll |

  This closes the 2.2a residual "recorded pane/pid not re-derived on restart": a
  daemon session that survived a `systemctl restart` now resumes with exact
  per-pane liveness, so the FIX B/C protections hold across a restart. `lived_s`
  from the marker timestamp closes the obs "in-memory, approximate across restart"
  residual.
- **Real log rotation** (`absd/rotate.py`) for `daemon.log` (stdlib
  `RotatingFileHandler`) and `events.jsonl` (`EventLog` → `maybe_rotate`):
  size-based (default 5 MB, configurable `log_max_bytes`), N generations
  (`.1`/`.2`/`.3`, default `log_keep=3`), atomic renames. **`iter_events` reads
  across rotated files** (`rotated_paths`, oldest-first + live), so the dashboard's
  timeline reconstruction survives a roll — the obs "reconstruction survives
  rotation" residual, closed.
- **Reboot notification** — per profile, once per boot, for any session that did
  not survive (recorded-but-dead, or a stale terminal `session.pid`): "🔄 Machine
  or daemon restarted; session `<label>` did not survive. Pool intact (`<n>`). ABS
  START to relaunch." Suppressed for blocked/off profiles.
- **`abs doctor`** — a new read-only diagnosis: core deps, unit present/enabled/
  active, linger, absd+aiohttp importable, tmux/herdr versions, config.json valid,
  events/pool 0600, and the last `error` event. Clear ✓/!/✗ lines with hints.
  (The plan said "extend the existing doctor" — there was none, so it is new.)
- **Installer** — `install.sh` (checkout only) offers `abs daemon install` + a
  quickstart and an optional **pinned herdr 0.7.5** (checksum-verified direct
  download, Linux/x86_64, never `curl | sh`). `uninstall.sh` stops+disables+removes
  the unit; `~/.abs` (profiles, **pools, recents**, logs) is removed only via the
  existing interactive prompt — never silent.
- **Docs** — README v3 section + command rows; CHANGELOG v3 story; GUIDE daemon
  walkthrough; the 1.8 acceptance run.

## Chaos test

`test_chaos_crash_recovery_converges`: 50 seeded (`Random(1337)`) iterations. Each
sets up a daemon session at a random liveness + a random pool, then a **fresh
poller reads only what's on disk** (simulating a process restart) and recovers.
Invariants asserted every iteration: converges to SESSION_LIVE iff the session
survived; **never polls the token while live** (the "no two consumers on one
token" invariant — a subsequent `poll_once` issues zero `getUpdates`); a dead
session → IDLE with the marker cleared; **the pool is never lost**. It passed on
the first run — no bug found. Honest caveat: it exercises the disk-state recovery
convergence, not a true `SIGKILL` at an arbitrary instruction (the daemon is a live
systemd service we must not kill); the marker's own crash-safety (written pre-launch,
pane recorded post-launch) is what makes the disk state always recoverable.

## Rotation design

`maybe_rotate(path, max_bytes, keep)` drops `.keep`, shifts `.k-1→.k … .1→.2`,
then live→`.1` — all `os.replace` (atomic on one fs), never raising. `EventLog`
calls it before each append; `daemon.log` uses stdlib `RotatingFileHandler` with
the same sizes. `rotated_paths` enumerates `.keep … .1` then live (chronological),
and `iter_events` concatenates them, so a reader sees a continuous stream. Config:
`log_max_bytes` (≥1024) and `log_keep` (≥1), validated; both files share them.

## Known gaps carried to Phase 2

- **`session_end.reason` doesn't distinguish crash vs clean exit** (engine exit code
  not threaded) — **Step 2.3**. Recovery reports a recorded-but-dead session as
  `exited` regardless of how it died.
- **Blocked-session notifications (G8, herdr `pane.agent_status_changed`)** — not
  built; **Step 2.1**. A remotely-started session that stalls on a prompt does not
  ping (the injected in-session prompt is the only nudge).
- **Pool/flow UX is text + two-button** — inline multi-select keyboards, statusline
  daemon dot, and richer `ABS STATUS` are **Step 2.2** proper (resume-first + the
  "/" menu were pulled forward; the rest wasn't).
- **`--prompt` pool content is visible in the launched process argv** (`ps`) — a
  file-based handoff would be more private; deferred.
- **Interactive-claude positional-prompt / `--continue` composition** is asserted
  only at the argv layer (no real claude in tests) — the human's live test confirms.
- **Chaos is convergence-only, not true SIGKILL-at-instruction**; a real kill-9
  fuzz harness is Step 2.3's chaos remit.
- **daemon.log/events rotation is size-only** (no time-based or compression) — fine
  for the volumes here; revisit if it ever matters.
- **`dead-poller` dashboard flag is a >180 s staleness heuristic**; and the doctor's
  "last error" reads only the live `events.jsonl`, not rotated generations.
