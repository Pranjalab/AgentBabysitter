# Critique — Step 1.1: Engine adapter with TmuxEngine

## What was built

- **`assets/abs.tmux.conf`** — tuned config loaded ONLY on ABS's isolated socket
  (`tmux -L abs -f <this>`), never the user's own tmux/`~/.tmux.conf`. `mouse on`,
  `history-limit 50000`, `set-clipboard on`, snappy `escape-time`, focus + aggressive
  resize, truecolor, and a minimal one-line status bar. No keybindings, no prefix
  remap — attach stays stock tmux. `remain-on-exit` deliberately left off (documented
  inline) because the liveness contract depends on it.
- **`absd/engines/tmux.py`** — `TmuxEngine` implementing the `Engine` protocol:
  - Isolated socket (`-L <socket>`, default `abs`, constructor-overridable for tests),
    tuned conf via `-f`, session name `abs-<profile>`.
  - `available()` = `tmux -V` exits 0. `create_session` (headless `new-session -d`,
    env via `-e` flags, argv after `--`, raises `EngineError` on duplicate).
    `is_alive`, `kill` (idempotent), `attach_command`/`attach_argv`, `list_sessions`.
  - All tmux calls go through one `_run` helper: `subprocess.run` with an argv list
    (never `shell=True`), a timeout, and `EngineError` on non-zero/missing-binary/
    timeout. Exact-target matching (`-t =name`) so `abs-work` never matches `abs-work2`.
  - Output parsing is **module-level pure functions** (`parse_pane_records`,
    `sessions_from_records`) — unit-tested without tmux (PLAN.md 4.4).
- **`absd/engines/__init__.py`** — `get_engine(name)` factory: `"tmux"` and `"auto"`
  both return `TmuxEngine` today; `auto` carries an explicit single-line TODO seam for
  HerdrEngine selection in Step 1.2 (D4 fallback). Unknown names raise `ValueError`.
- **`absd/engines/cli.py`** — `python -m absd.engines.cli` with argparse: `sessions
  [--json]` and `attach [profile]`. Human table via pure `format_sessions_table`.
  `attach` resolves the target (named, or the sole live one) and `os.execvp`s tmux so
  the user lands in the session; no live session → helpful stderr message + exit 1.
- **`abs.sh`** — `cmd_engine` shim + `sessions|attach` in the pre-jq dispatch block
  (no profile/jq needed, like `daemon`). Resolves the venv python relative to
  `SCRIPT_PATH` (not `python3` on PATH), sets `PYTHONPATH`, and `exec`s the adapter so
  `abs attach` is bash → python → tmux with nothing in between. Help text updated.
- **Tests** — `tests/test_engine_tmux.py`, 18 tests. Full suite: **49 passed**
  (31 pre-existing + 18 new).

## What is tested

- **Pure/no-tmux:** pane-record parsing (well-formed, blank/malformed skipped, non-int
  pid → None), session folding (non-`abs-` filtered, alive-if-any-pane-live, sorted,
  cwd/pid), `attach_command` exact string (default + custom socket), `get_engine`
  factory (tmux/auto/errors), protocol `isinstance`, table formatting.
- **Integration (real tmux, throwaway `-L abs-test-<random>` socket):** full lifecycle
  (create → alive → `SessionInfo` cwd/name/pid/alive correct → kill → dead → gone);
  env reaches the *command process* (fake-claude's `$$` written from `$FAKE_CLAUDE_PID_FILE`
  equals the pane pid — proof the `-e` var reached the launched process, not just the
  session env); two profiles independent kill (G5 seed); duplicate create raises;
  `is_alive` false after the command self-exits (crash-after-1, polled, no fixed sleep);
  `available()` true; `kill` idempotent on a missing session.
- Every integration test kills its whole server AND unlinks the socket file in
  teardown (even on failure). Verified: after the full suite, zero tmux processes and
  zero leftover socket files. The user's default socket is never named or touched.

## What is NOT tested (by design / later steps)

- **Human attach UX** (mouse scroll on the tuned conf, detach) — needs a real TTY;
  it is Pranjal's manual checklist (`docs/v3/manual-tests/1.1.md`), not automatable
  here. `os.execvp` into `tmux attach` fails without a TTY, so the exec *target* is
  unit-verified (`attach_argv`) but the exec itself is only exercised manually.
- **The real launcher inside a pane.** Tests run `fake-claude`, not
  `abs --daemon-start` (that flag lands in Step 1.5). The pane-command shape is
  identical, but the launcher's real behavior in a pane is unproven here.
- **HerdrEngine / `auto` selecting herdr** — Step 1.2. `auto` == tmux today.
- **Concurrency beyond two sessions / daemon integration** — Steps 1.3–1.4.

## Known gaps / what would break first in production

1. **`pane_current_path` drift.** `list_sessions().cwd` reports the pane's *current*
   working dir, not a stored "session cwd". If the launched process `cd`s elsewhere,
   `cwd` follows it. fake-claude and the real launcher stay put, so this is correct
   today, but a future in-session `cd` would make the reported cwd surprising. tmux
   offers no "session start dir" field, so this is the honest best available.
2. **Socket-file litter, not server litter.** `tmux kill-server` reaps the server
   process but leaves the zero-byte socket inode in `/tmp/tmux-<uid>/`. Tests now
   unlink it; the real daemon (1.3+) should be aware that a lingering socket file does
   NOT mean a live server — liveness is `has-session`, never socket-file presence.
3. **Env values are visible to same-user processes.** `-e KEY=VALUE` keeps values out
   of the pane's *command line* / `ps` / pane title (better than an `env` prefix), but
   the tmux session environment is readable via `tmux show-environment` by any same-
   user process. That is fine for the non-secret launcher vars we pass; **secrets must
   never be passed this way** (PLAN.md 5.5). Flagged for whoever wires real env in 1.5.
4. **`available()` and `_run` shell out per call.** Cheap locally; a wedged tmux server
   is bounded by the 10s timeout → `EngineError`. No ret/backoff — the daemon layer
   owns retry policy, not the engine.

## Deviations from PLAN.md

- **`EngineError` lives in `tmux.py`, not `base.py`.** `base.py` is the intentionally
  implementation-free protocol module (Step 0.1). I kept the exception engine-local; if
  HerdrEngine wants to share it in 1.2, promote it to `base` then. No protocol change
  was needed — `base.py` is **unmodified**. (Justified judgment call, not a plan
  contradiction.)
- **`attach_argv` added to `TmuxEngine`** (not in the protocol). The protocol keeps
  `attach_command() -> str` exactly as PLAN.md 4.2 specifies; `attach_argv` is a
  concrete convenience for `os.execvp`. The CLI could equally `shlex.split` the string;
  the method just avoids a re-parse. Nothing tmux-specific was added to the protocol.
- **`abs attach [profile]` accepts an optional positional** and also honors the global
  `--profile`. PLAN.md 1.1 writes `abs attach <profile>`; the optional form (attach the
  sole live session) is strictly a convenience and matches the "with one, just attach"
  wording in the work package.

## Critique-gate question: is the interface honest? Did anything tmux-specific leak?

**No leak.** The `Engine` protocol (`base.py`) is untouched and carries nothing tmux-
shaped: no socket, no session-name format, no tmux flags, no `-L`/`-f`. `attach_command`
returns an opaque shell string (herdr will return its own). `SessionInfo` is a neutral
value type. All tmux vocabulary — sockets, `has-session`, `pane_dead`, `-e` env,
`abs-<profile>` naming — is confined to `tmux.py`. `get_engine` hides the backend choice
behind a name. The one honesty caveat is `list_sessions().cwd` semantics (gap 1): it is
"current pane path", and the protocol docstring should not over-promise a frozen cwd —
worth a one-line protocol doc tweak in 1.2 if it matters, but not a leak.
