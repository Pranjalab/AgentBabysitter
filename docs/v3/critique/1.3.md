# Critique — Step 1.3: absd daemon skeleton + single-profile poller (read-only)

## What was built

- **`absd/telegram.py`** — async Bot API client (aiohttp): `get_updates`
  (long-poll, offset), `send_message`, `edit_message_text`,
  `answer_callback_query`, `set_my_commands`. Constructor takes `token` +
  `base_url` (tests point it at FakeTelegram). Per-request timeouts, one retry
  on a transient network error, HTTP 409 surfaced as the distinct `Conflict409`
  (a `TelegramError` subtype). Token is private (`_token`) and `__repr__`
  redacts it — never logged.
- **`absd/pool.py`** — per-profile `pool.jsonl`: `append` (0600, `O_APPEND` +
  fsync), `read_all` (corruption-tolerant, counts skips), `existing_update_ids`
  (dedupe), `unforwarded`, `mark_forwarded` (keeps records, D14), `clear`.
  ISO-8601 UTC timestamps.
- **`absd/profiles.py`** (new) — read-only discovery from an ABS_HOME root:
  profile names, tg-dir resolution (rc.json `.tg_dir` else `default_tg_dir`),
  token from `.env`, allowlist + `dmPolicy` from `access.json`, `.blocked` from
  rc.json, live-session detection (`session.pid` + `os.kill(pid,0)`), and the
  `should_poll()` gate that folds live/blocked/off together. **No write path.**
- **`absd/daemon.py`** (new) — the IDLE_POLLING `Poller`: yields when
  `should_poll()` is false, long-polls, allowlist-first, exact command grammar
  (`ABS STATUS`/`ABS POOL`), pools everything else with the exact acks, advances
  the offset only after the pool is persisted, dedupes redelivery, 409 backoff.
- **`absd/__main__.py`** — real entry: `--abs-home`/`--config`/`--once`/
  `--log-level`, config load+validate, discovery, one staggered task per
  profile, SIGTERM/SIGINT shutdown, stderr+file logging with a crude size cap.
- **`assets/absd.service`** + `abs daemon install|start|stop|status|logs|run`
  (renders the user unit, does NOT enable/start, prints linger status).
- **72 new tests** (148 total, green): allowlist, silence-for-strangers,
  STATUS/POOL, case-insensitivity, near-miss pooling, pool 0600/round-trip/
  corruption/dedupe/D14, crash-safety, 409 backoff, live-session yield,
  blocked/off yield, config validation, profile discovery, `--once` e2e.

## Security gate — line-by-line against PLAN.md 5.1–5.3

### 5.1 Allowlist first (also D10)
- **Enforced by:** `Poller._handle` (`absd/daemon.py`) checks
  `self.profile.is_allowed(ex.from_id)` as the **first** action on every update,
  before any command parsing or pooling. Non-allowlisted → local `log.debug`,
  no `send_message`, no `pool.append`. The offset still advances because the
  batch's `max_uid` is computed over *all* updates (`_process_batch`), including
  dropped ones. `Profile.is_allowed` (`absd/profiles.py`) compares
  `str(from_id)` against `access.json`'s `allowFrom` — which holds **strings**
  (see "on-disk formats" below); a naive int compare would have silently
  rejected every allowed user.
- **Proven by:** `test_stranger_silence_offset_advances_nothing_pooled`
  (no sendMessage, nothing pooled, offset advanced), `test_allowlist_string_compare`
  (int `from.id` matches string allowlist), `test_allowlisted_message_pooled_and_acked`.

### 5.2 Fixed grammar while unattended (D9)
- **Enforced by:** `normalize_command` (strip + uppercase, **no** internal-
  whitespace collapse) and `is_status`/`is_pool_cmd`/`is_start` — exact
  whole-message equality only. `_handle` runs the two read commands and pools
  *everything else*, including unknown `ABS`-prefixed text, near misses, and
  `callback_query` (which is never treated as a command). No free-text path; the
  daemon has no model.
- **Proven by:** `test_near_miss_pools_not_executes` (`"ABS  STATUS"`,
  `"abs status extra words"`, `"ABSSTATUS"` all pool, not execute),
  `test_abs_status_case_insensitive`, `test_normalize_and_status_matcher`,
  `test_callback_query_pools_and_answers`.

### 5.3 Telegram can never: name a path / change the allowlist / unblock / re-enable OFF / alter config
- **Enforced structurally:** the daemon's entire write surface is (a)
  `pool.jsonl` and (b) `~/.abs/daemon/poller-<p>.json` (offset). It has **no
  code path** that writes `access.json`, `rc.json`, or `config.json`, and no
  command verb for paths/allowlist/config — the grammar is two read verbs plus
  "pool it". `ABS OFF`/`ABS BLOCK` are honored (polling stops via
  `Profile.is_off`/`is_blocked` in `should_poll`) but only ever *cleared* from
  the terminal: `abs on` (`cmd_on`) refuses while `.blocked`, and `ABS START`
  isn't wired (pools with a distinct ack).
- **Proven by:** `test_off_does_not_poll`, `test_blocked_does_not_poll`
  (0 getUpdates calls, nothing pooled), plus the absence of any writer in
  `absd/profiles.py` (read-only by construction) — asserted implicitly by every
  discovery test reading fixtures the daemon never mutates.

### 5.5 Secrets discipline (supporting)
- **Enforced by:** `TelegramClient._token` private + redacting `__repr__`; token
  only ever in the request URL. Pool + config + offset files are 0600
  (`absd/pool.py`, `absd/config.py`, `Poller._save_offset`).
- **Proven by:** `test_token_never_in_repr`, `test_append_creates_file_0600`,
  `test_append_tightens_loose_perms`, `test_load_enforces_0600`.

## On-disk formats mirrored from abs.sh (and surprises)

| File | abs.sh source | Shape the daemon reads |
|------|---------------|------------------------|
| `profiles/<p>/rc.json` | `write_state` / `state_set` | JSON obj; daemon reads `.tg_dir` and `.blocked` (BLOCK) |
| `<tg_dir>/.env` | `save_token` / `load_token` | one `TELEGRAM_BOT_TOKEN=<t>` line; quotes+ws stripped |
| `<tg_dir>/access.json` | `write_access` / `set_policy` | `.allowFrom` (**strings**), `.dmPolicy` (`"disabled"` = OFF) |
| tg_dir resolution | `default_tg_dir` / `use_profile` | rc.json `.tg_dir` else `~/.claude/channels/telegram[-<p>]` |
| `profiles/<p>/session.pid` | `cmd_run` (~2485) | one decimal PID; live iff `os.kill(pid,0)` succeeds |

**Surprises (called out):**
1. `allowFrom` holds **strings**, not ints (`jq --arg`). The allowlist compare
   is string-based to match; this is the single most likely place a careless
   port breaks 5.1.
2. **OFF is not in rc.json.** It lives in *access.json* `dmPolicy == "disabled"`
   (`set_policy disabled`). **BLOCK** *is* in rc.json (`.blocked`). Two flags,
   two files, two different terminal-only recovery paths (`abs on` vs
   `abs setup`). Both honored in `Profile.should_poll`.
3. The file PLAN.md calls `state.json` is on disk `rc.json`. PLAN.md 4.3 also
   anticipates a future `.daemon_blocked` field; abs.sh does not write one today,
   so 1.3 keys off the *existing* `.blocked` — no new field invented.

## Crash-safety: the injection seam

- **Seam:** `Poller.on_batch_persisted` — an optional awaitable called inside
  `_process_batch` **after** every pooled message is durably appended+acked and
  **before** `_save_offset`. A test sets it to raise, reproducing a crash in
  exactly that window.
- **Ordering contract:** pool append (fsync) → seam → offset commit. A crash in
  the window leaves the pool written but the offset uncommitted; on restart the
  fresh poller resumes from the last *committed* offset (None here), re-fetches
  the same batch (still pending on Telegram/the fake), and `existing_update_ids`
  dedupe skips the already-stored `update_id` — no loss (D14), no duplicate, no
  second ack.
- **Proven by:** `test_crash_between_pool_and_offset_no_loss_no_dup` — crashes
  at the seam (pool=1, offset file absent, 1 ack), then "restarts" a new poller
  → pool still 1, still 1 ack, offset now committed to `poller-default.json`.

## What executed for real vs temp-HOME (systemd path)

- **Real:** `abs daemon install`, `run --once`, and `status` were run with
  `HOME`/`XDG_CONFIG_HOME`/`ABS_HOME` pointed at scratchpad temp dirs. The unit
  rendered correctly to the temp `.config`; `systemctl --user daemon-reload` ran
  (harmless — it rescans the *real* unit dir, which never received our file);
  `run --once` against an empty temp ABS_HOME discovered 0 profiles and exited 0
  with **no network**.
- **NOT executed:** no write to the real `~/.config/systemd`, no
  `systemctl enable/start`, no `enable-linger`, and **no getUpdates against
  api.telegram.org, ever**. Every automated test uses FakeTelegram on 127.0.0.1.
  The real-bot live run is Pranjal's (manual-tests/1.3.md).

## What is NOT tested / known gaps (what breaks first in production)

- **shellcheck could not be run** — the binary isn't installed in this env, so I
  could not diff against the 22-finding baseline. The new `cmd_daemon` follows
  the existing quoting/`die`/`case` patterns (mirrors `cmd_engine`); this needs a
  real `shellcheck abs.sh` on a machine that has it before merge. **First thing
  to verify.**
- **TOCTOU between `should_poll()` and `getUpdates`.** A terminal launch that
  writes `session.pid` microseconds after the poller passed the check will still
  fire one `getUpdates`; PLAN.md 4.1 accepts this and the 409 backoff (plugin
  owns the token) covers it. Not separately tested here.
- **Offset is committed to Telegram lazily** — locally persisted first, then the
  *next* `getUpdates(offset=...)` confirms it server-side. Correct and crash-safe
  (dedupe covers a crash before the next poll), but a reader expecting an eager
  server-side commit per batch should note this.
- **HANDOFF / SESSION_LIVE / RECLAIM not implemented** — only the IDLE_POLLING
  yield (the 4.1 note) is. Full state machine is Step 1.5. `ABS START` pools.
- **Log rotation is crude** (size cap + one `.old` roll). Real rotation is 1.8.
- **Multi-profile is structural, not stress-tested** — the loop-over-profiles
  and per-profile stagger exist, but only single-profile behavior is asserted;
  independence/one-409-doesn't-affect-others lands in 1.4.
- **Callback pooling stores raw `data` as text.** Fine for a pool preview; the
  ABS START flow (1.5) will interpret callbacks instead of pooling them.
- **`answer_callback_query` failures are swallowed** (best-effort) so a flaky
  answer never drops the pool/ack — intentional, but means a persistently broken
  answerCallbackQuery would be invisible except in debug logs.

## Deviations from PLAN.md

- Added `ABS_TELEGRAM_BASE_URL` as a **test-only** env seam so `python -m absd`
  points at FakeTelegram in the `--once` e2e test. Documented in
  `__main__.py`; unset in production (defaults to api.telegram.org). Without it,
  an end-to-end test of the entry point couldn't avoid real Telegram.
- Two Step-0.1 skeleton tests (`test_skeleton.py`) asserted the stubs raise
  `NotImplementedError`; those assertions are now obsolete (the stubs are
  implemented) and were rewritten to assert the real behavior. No coverage lost.
