# Critique — Step 0.2: herdr headless spike (go/no-go gate)

## Verdict: **GO** — HerdrEngine proceeds as primary (behind `auto`, D4)

The full headless lifecycle works reliably with **no client ever attaching**,
driven entirely by herdr's CLI + JSON socket API. A named-session server starts
headless, a workspace is created at an arbitrary cwd, a long-lived launcher runs
in a pane, liveness is detectable two independent ways, the pane is attachable
without a TTY (and by a human with one), and kill/stop leaves no orphans. The
agent-status event stream — the thing Phase 2.1 needs and the thing tmux can
never give us — fires for a real `claude`. Nothing here forces the GO: it is a
clean pass. D4 still holds — herdr stays an *enhancement* gated behind `auto`,
and every Phase-1 test must also pass on tmux.

This is a GO for **viability**, not an unconditional endorsement: see fragilities.
The default engine can still be flipped to tmux at any time (D4) — e.g. if
Pranjal's UI evaluation disappoints — with zero impact on the daemon contract.

## What was built / proven

- **Pinned install (D13):** herdr **0.7.5** (latest stable, `prerelease:false`),
  `herdr-linux-x86_64`, curl'd directly from the GitHub release to
  `~/.local/bin/herdr` (no `curl | sh`). Version + URL + SHA-256 recorded in
  `docs/v3/herdr-recipes.md`. Channel left at `stable`, no `herdr update` run.
- **`tests/integration/herdr_spike.sh`** — non-interactive, runs lifecycle
  items 1–6, per-step `ok/FAIL` echo, **exit 0** on success. Uses a unique
  session name (`abs-spike-test-$$`) and an `mktemp` scratch cwd (never the
  repo). `trap … EXIT INT TERM` stops+deletes the session and removes the
  scratch dir even on failure. Skips cleanly (`SKIP: herdr not installed`,
  exit 0) when herdr is absent — both paths verified (PASS run + SKIP run).
- **Item 7 events** proven manually with the real logged-in `claude`; verbatim
  `pane.agent_status_changed` JSON (`idle`/`working`/`idle`) captured in the
  recipes doc. Not in the script (needs a logged-in claude + human observation).
- **`docs/v3/herdr-recipes.md`** — every working command/socket call verbatim,
  socket-path facts, first-run footprint, and the dead ends below.

## What is fragile (weight these before leaning hard on herdr)

- **Pre-1.0, single maintainer, protocol churn (R3).** Protocol is at version
  17; the CLI surface is large and still moving. We are pinned (D13) and the
  adapter isolates it, but every version bump needs the spike re-run. The recipes
  are version-stamped for exactly this reason.
- **`herdr server` readiness is a poll, not a signal.** The socket file appears a
  beat before the server accepts calls; the script polls `session list` for
  `running:true`. A slower box could need a longer poll budget than the 50×0.2s
  used — generous, but wall-clock.
- **`agent prompt --wait` false-negatives (`agent_prompt_stalled`) on fast turns.**
  herdr requires an observed `working` flip within 5 s; a sub-5 s answer looks
  "stalled" though it succeeded. HerdrEngine must never gate on this error.
- **`blocked` detection is screen-manifest-based and strict.** Claude Code is not
  a lifecycle authority in herdr — blocked is inferred from matching known
  approval UI in the bottom-buffer snapshot. New/unusual prompts can read `idle`
  until herdr learns the shape. Phase 2.1 debounce/latency must budget for this,
  and for false negatives.
- **Detection depends on herdr's remote manifest fetch.** herdr pulls agent
  detection manifests from herdr.dev on first server run. Offline or if that
  endpoint changes, detection quality can regress. `[update] manifest_check=false`
  pins to bundled manifests if we need determinism.

## What is NOT proven (honest gaps)

- **`blocked` status never captured.** This machine's claude auto-approved the
  trivial `echo` command (its own permission config; ABS approved nothing), so
  the run went `working → idle`, never `blocked`. G8/Phase-2.1 rests on `blocked`
  arriving reliably — that is deferred to Pranjal's interactive manual test
  (`docs/v3/manual-tests/0.2.md`) and must be re-proven before Step 2.1 is
  greenlit. Today we have proven the *transport* (events.subscribe delivers
  status changes) and two of the states, not the blocked state itself.
- **No human attach yet.** Attachability is proven non-interactively via
  `terminal session observe` (frames stream). Actual mouse-scroll / detach UX —
  and the deferred UI evaluation — is Pranjal's manual checklist, not proven here.
- **Single session only.** The spike ran one named session. Multi-session
  concurrency (G5: three herdr servers at once) is asserted by design (each named
  session is an independent server + socket) but not exercised until Step 1.4.
- **No restart/handoff/crash behavior.** Server-restart snapshot restore, live
  handoff, and daemon-crash-with-live-session recovery are untouched (Steps
  1.4/1.8). We only proved the happy-path create→run→kill.
- **No `abs.sh --daemon-start` yet.** The pane ran fake-claude, not the real
  launcher (that flag doesn't exist until Step 1.5). The `pane run` recipe is the
  same shape, but the real launcher's behavior inside a herdr pane is unproven.

## Deviations from PLAN.md

- PLAN 4.2 guessed the recipe might be socket `workspace.create` + `pane.run`.
  The **CLI wrappers** (`herdr workspace create` / `herdr pane run`) are the same
  control surface and are what I used and documented — simpler for a bash-driven
  adapter, and they emit the same JSON. Raw socket is only needed for the
  long-lived `events.subscribe` stream (item 7), which the CLI does not wrap.
- PLAN 0.2 suggested `htop` as the long-lived pane process; I used the repo's
  `tests/harness/fake-claude --mode normal` instead (it is ready, writes a
  session.pid, and matches the real launcher's process shape).
- Item-7 blocked state not captured (see gaps) — a deviation from the ideal, made
  explicit rather than forced.

## What would break first in production

1. **A herdr point release changes a CLI flag or JSON key.** The adapter parses
   `.result.root_pane.pane_id` and greps `pane process-info` — a rename breaks
   session creation or liveness silently. First defense: the pinned version +
   re-running `herdr_spike.sh` on every bump (it is the canary).
2. **`blocked` never fires (or fires late) for a real approval prompt.** If
   Phase 2.1 ships on the assumption that blocked is prompt and reliable, users
   get missed or laggy "waiting for you" pings. Must be re-validated with a real
   Normal-mode block before 2.1.
3. **Server readiness race under load.** If the daemon issues `workspace create`
   before the backgrounded `herdr server` accepts calls, creation errors. The
   engine must poll `session list` (as the script does), not assume readiness.

## Security notes (PLAN 5)

- Spike cwd was an `mktemp` scratch dir, never the repo, never `~/.abs` or
  `~/.claude`. No credential files were read. The real claude ran normally
  (logged-in binary) and self-approved a harmless `echo`; ABS approved/denied
  nothing and the pane was killed immediately after.
- The herdr socket is **not** a security boundary (PLAN 5.7): any same-user
  process can drive it. ABS must never delegate a trust decision to herdr state.
- No herdr or claude processes left running (verified `pgrep herdr` / `pgrep
  claude` empty); no repo pollution (only the four Step-0.2 deliverables added).

## Pre-existing orphan finding (not mine, but flag it)

`ps` showed six orphaned `sleep 3600` processes (PPID 1) timestamped 00:53–00:56,
i.e. **before** this spike (which started 01:04). They are leftovers from the
Step 0.3 fake-claude harness pytest runs: `fake-claude --mode normal` backgrounds
`sleep 3600 & wait`, and its SIGTERM trap does `cleanup; exit 0` **without**
killing that child — so a bare `proc.terminate()` orphans the sleep to init.
(herdr's `pane close` kills the whole group, so the spike itself leaked nothing.)
Two follow-ups for later steps: (a) fake-claude should `trap … kill "$sleep_pid"`
before exit so the harness stops leaking; (b) the daemon's future orphan-cleanup
logic must not assume a parent SIGTERM reaps children. I left the six sleeps alone
(not mine to kill; they self-exit within the hour).
