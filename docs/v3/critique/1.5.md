# Critique — Step 1.5: ABS START flow + HANDOFF + RECLAIM (the headline feature)

## Live-demo findings (2026-07-23) — three real bugs, fixed

The human ran the headline demo end-to-end: handoff at 15:21 launched claude in
`~/Projects/llm` via herdr, the session ended ~15:25, RECLAIM completed. It worked
— and surfaced three bugs the fakes had not, each now fixed with tests. Honest
root causes:

1. **RECLAIM left the engine session behind (herdr).** Root cause: herdr keeps the
   pane and its interactive shell alive *after* the launched command exits (the
   very property `HerdrEngine.is_alive` keys off — `fg_pgid == shell_pid` once
   claude is gone). So `is_alive` correctly went false, but the herdr *session*
   stayed "running" with a bare shell. The daemon's RECLAIM only probed Telegram
   and resumed polling; it never told the engine to tear the session down. The next
   handoff then hit `create_session` → "session 'abs-default' already running". The
   fakes missed this because `TmuxEngine` (and the FakeEngine) destroy the session
   when the command exits — only herdr keeps it. **Fix:** RECLAIM now calls
   `engine.kill(profile)` up front (before polling resumes; errors tolerated), and
   HANDOFF is self-healing — a create collision with **no genuinely live session**
   (no live `session.pid`) kills the stale engine session and retries once; a
   collision **with** a live session refuses with the attach hint (never clobbers a
   real session). Tests: `test_reclaim_tears_down_leftover_engine_session`
   (parameterized tmux+herdr, stub launcher), `test_handoff_self_heals_stale_session`,
   `test_self_heal_refuses_when_genuinely_live`, `test_reclaim_kills_engine_session`.

2. **`abs attach` / `abs sessions` looked in the wrong engine.** Root cause:
   `absd/engines/cli.py` defaulted to tmux (`$ABS_ENGINE` fallback `"tmux"`), but
   the daemon launches via `config.json` (`"auto"` → herdr). So while the human's
   herdr session ran, `abs attach default` searched tmux, found nothing, and left
   him unable to reach the running pid. **Fix:** the CLI default now resolves the
   *same way the daemon does* (`resolve_default_engine_name` → `config.json` engine,
   `$ABS_ENGINE`/`--engine` still explicit overrides); with no override, `abs
   sessions` lists across **both** available engines (ENGINE column) and `abs
   attach` searches both and attaches whichever owns the session (clear error if
   both do). Tests: `test_resolve_default_follows_config` (+ env override + missing),
   `test_sessions_lists_across_engines`, `test_attach_resolves_single_owner` and the
   ambiguity/empty cases.

3. **Contradictory failure message + unreachable session.** "⚠ Couldn't start the
   session (session 'abs-default' already running). Nothing is running." was both
   self-contradictory and unhelpful, and the confirmation's generic `abs attach`
   hint didn't tell him how to connect. **Fix:** after bug 1's self-heal this exact
   case normally *succeeds* (with a "♻️ found a leftover, cleaning it up, retrying…"
   note); a genuine final failure now states what happened + one actionable step
   (`abs daemon logs`); and the HANDOFF confirmation includes the **exact**
   `engine.attach_command(profile)` for the engine used, not a generic hint.

The rest of this critique is the original 1.5 self-review; the sections below still
hold, with the three fixes folded in.

## What was built

- **`absd/flow.py`** — pure ABS START helpers (no I/O except directory scans):
  the D6 folder-name jail (`validate_folder_name` + `safe_join_under_root`),
  project-option enumeration (`enumerate_project_options`: registered projects →
  workspace children → "➕ New folder"), inline-keyboard + numbered-text renderers,
  the callback-data grammar (`as:p:<i>` / `as:nf` / `as:m:n` / `as:m:a`) and its
  parsers (`choose_project` / `choose_mode`), and `build_launcher_argv` (the exact
  `bash <SCRIPT_PATH> --profile <p> --daemon-start [--away]`).
- **`absd/registry.py`** — `registry.json` (list of `{path,label,added_at}`, 0600)
  with `add`/`list`/`remove`, plus a `python -m absd.registry` CLI
  (`project add|list|rm`, `workspace-root [<dir>|--show]`) that `abs.sh` shells
  into. Registration is **terminal-only** (5.3) — no Telegram code path writes it.
- **`absd/daemon.py` — the state machine** extended from IDLE_POLLING to the full
  4.1 set: the flow (`_begin_flow`/`_advance_flow`/expiry), HANDOFF (`_do_handoff`),
  SESSION_LIVE watch (`watch_once`), and RECLAIM (`reclaim`). `run()` now dispatches
  on `session_state` (idle / session-live / reclaim); `poll_once` stays the IDLE
  primitive and triggers the handoff at the end of the completing batch.
- **`abs.sh`** — `--daemon-start` and `--away` global flags; `cmd_run` honours
  `--daemon-start` (dies loudly if unpaired, skips the flood + update prompts,
  otherwise identical — hooks, prompt, `session.pid`, `exec claude`); `--away`
  reuses the `ABS_AWAY` → `acceptEdits` mechanism. New `abs project add|list|rm`
  and `abs config workspace-root <dir>` shell into the Python registry CLI.
- **`assets/absd.service`** — moved `StartLimitIntervalSec`/`StartLimitBurst`
  from `[Service]` to `[Unit]` (systemd was warning "Unknown key, ignoring").
  **Requires the human to re-run `abs daemon install` + `systemctl --user
  daemon-reload`** for the fix to take effect (noted in the manual test).
- **`absd/__main__.py`** — builds one shared engine (`get_engine(cfg.engine)`) for
  the whole daemon (so `list_sessions` counts across profiles for max_sessions),
  wires it + the abs.sh path + a daemon-wide session counter into every poller.

## Flow-state design (per-profile, timeout, fallback)

One in-memory `Flow` per poller (`chat_id`, `step` ∈ project/folder/mode,
`options`, `started_at` monotonic, `chosen_path`, `label`); never persisted, so a
crash or a new `ABS START` restarts from scratch. Timeout: `_expire_flow_if_needed`
runs once per poll cycle — a flow older than `flow_timeout_s` (300s) is dropped
with the "timed out" notice. Fallback: every step accepts BOTH the inline-keyboard
callback and the numbered-text reply in the same step (`choose_project`/`choose_mode`
try callback data first, then parse the message as a number), so a client whose
keyboard misbehaves still drives the whole flow.

## HANDOFF — exact ordering + the single offset commit

`_do_handoff` (reached from `poll_once` right after the batch that completed the
flow, i.e. *outside* the poll loop):

1. **Leave the poll loop** — structural: `session_state` flips to `session-live`
   at the end, and `poll_once` early-returns for any non-idle state, so the daemon
   never polls this token again until RECLAIM.
2. **Single offset commit** — `getUpdates(offset=last+1, timeout=0)`. This is the
   ONE dedicated server-side commit; `_process_batch` had already advanced the
   local offset to `last+1`, and this call confirms it so the plugin resumes
   cleanly. Recorded in `handoff_committed_offset` (FakeTelegram asserts
   `confirmed_offset == 4` and `handoff_committed_offset == 4` for a 3-update flow).
3. **Write `daemon-handoff.json`** (timestamp, project, mode, chat_id; 0600 atomic).
4. **`engine.create_session`** with the reused launcher argv + `{ABS_HOME}` env, in
   the chosen cwd. A launch failure clears the marker, notifies, and returns to IDLE.
5. **Confirmation** message with the `abs attach <profile>` hint.
6. **→ SESSION_LIVE**.

## RECLAIM — signals reconciled, grace/backoff

`_session_dead()` reconciles **both** signals: dead only when *neither*
`session.pid` (`os.kill(pid,0)`) is alive **nor** `engine.is_alive()` reports the
session alive — the safe bias, so a single flapping/racy signal never triggers a
premature reclaim (proven on real tmux AND herdr in `test_daemon_engine.py`).
`watch_once` also bounds the *startup* window: a launch that never comes alive
within `session_start_grace_s` (30s) is reclaimed as a failed start (crash /
login — full detection is Step 1.6). `reclaim`: grace delay (`reclaim_grace_s`,
5s) → probe `getUpdates(timeout=0)` → on 409 exponential backoff
(2,4,8… capped at `reclaim_backoff_max_s`, 60s) → on success clear the marker,
send "⏹ Session ended", resume IDLE. The probe does **not** advance the offset, so
messages that arrived after the session died are re-fetched and pooled by the next
idle poll (D14 — never lost).

## Hostile-reviewer walkthrough — "what can a stolen phone do?"

Threat model: an attacker holds an unlocked, allowlisted phone (they *are* on the
allowlist — otherwise 5.1 drops every update silently). Every flow input:

| Input | What it can do | What jails it |
|-------|----------------|---------------|
| `ABS START` | Start a session — **only in a project the operator already exposed**. | The project keyboard is enumerated from `registry.json` + `workspace_root` children — both **terminal-only** (5.3). The phone can never *name* a project. |
| Project pick (`as:p:<i>` / number) | Selects an existing option by index. | Index is bounds-checked against the flow's own option list; an out-of-range or stale callback selects nothing (re-prompt). |
| "➕ New folder" → name | Creates a directory. | **Two gates:** `validate_folder_name` (regex `[a-zA-Z0-9._-]{1,64}`, rejects `/`,`\`,NUL,`.`,`..`,spaces,unicode,>64) **and** `safe_join_under_root` (resolves and asserts the parent is *exactly* the workspace root). `../evil`, `/etc`, absolute paths — all rejected; a created folder can only ever land directly under the root (D6). Proven by `test_new_folder_rejects_bad_names` + `test_new_folder_stays_jailed_under_root`. |
| Permission pick (Normal/Away) | Chooses `acceptEdits` for the launched session. | Away only relaxes *file-edit* prompts; the v2 Bash guard hook, the destructive-command block, and the whole kill ladder are inherited unchanged because the daemon launches through `abs.sh` (5.4). "Away" is still a real session the operator can `ABS EXIT`/`ABS STOP`. |
| A stray callback / expired menu | Nothing. | Answered ("menu expired"), never pooled, never acted on. |
| Rapid `ABS START` spam | At most `max_sessions` live sessions across all profiles; each start is a project the operator exposed. | `_at_session_cap` counts `engine.list_sessions()` alive; over the cap → refusal message, no flow. |
| `ABS START` for another profile's bot | Nothing — bot identity IS the profile (D9); a bot only ever starts its own profile. | Structural: one poller per token, each bound to one profile. |

**Residual risks (honest):**

1. **An exposed project is fully actionable.** Once a directory is registered (or
   sits under the workspace root), a stolen phone can launch a real Claude Code
   session *in it* and drive it. D6 constrains *where*, not *what* — the session's
   own guard/kill-ladder is the in-session defence, and terminal-only OFF/BLOCK
   (D11) is the recovery. This is by design (G2), but it is the real blast radius:
   **register only projects you accept remote starts into, and keep the workspace
   root scoped.** Documented for the operator in the manual test.
2. **Away mode auto-accepts file edits.** A stolen phone can pick Away and let the
   session edit files without prompts. Bash/destructive commands still prompt/guard;
   still, Away widens the window. Mitigated by per-start choice (D5, Normal default)
   and the operator-visible confirmation naming the mode.
3. **`daemon-handoff.json` stores `chat_id`.** A plan-additive field (the plan
   lists timestamp/project/mode). It is 0600 local user data and holds only a
   Telegram chat id (already in `rc.json`); needed so RECLAIM knows where to send
   "session ended". No secret exposure, but it is a deviation — see below.
4. **Login detection is not here (Step 1.6).** A start against an unpaired profile
   dies loudly at the launcher (`--daemon-start` → "not paired"); a launch that
   never comes alive is reclaimed after the startup grace with a generic "session
   ended" rather than a "please log in" message. The predefined login message lands
   in 1.6.
5. **Stale-handoff on boot clears silently.** `check_stale_handoff` clears a marker
   with no live session and logs a warning but does **not** send a phone notice —
   deliberately, to avoid a spurious "session ended" on every daemon restart. The
   2.3 full treatment adds crash-vs-clean distinction.

## HANDOFF timing diagram (vs 4.1)

```
IDLE_POLLING
   │  getUpdates(offset=N)   ← flow updates arrive across cycles
   │  … project pick … mode pick (last update id = L)
   │  _process_batch: local offset = L+1
   ▼
HANDOFF  (_do_handoff, outside the poll loop)
   │  (2) getUpdates(offset=L+1, timeout=0)   ── THE single offset commit
   │  (3) write daemon-handoff.json {ts, project, mode, chat_id}
   │  (4) engine.create_session(profile, cwd, [bash abs.sh --profile p --daemon-start], {ABS_HOME})
   │  (5) sendMessage "🚀 Started … / abs attach p"
   ▼
SESSION_LIVE  (watch_once every ~3s; no Telegram traffic for this bot)
   │  engine.is_alive AND session.pid reconciled
   │  … session dies (or never came alive within 30s) …
   ▼
RECLAIM  (reclaim)
   │  sleep reclaim_grace_s (5s)
   │  getUpdates(timeout=0)  → 409? backoff 2,4,8…≤60, retry ; else proceed
   │  clear marker ; sendMessage "⏹ Session ended"
   ▼
IDLE_POLLING   (next poll re-fetches + pools anything that arrived after death)
```

This matches 4.1 exactly: single commit at handoff, marker file, engine launch,
liveness watch, grace delay, 409 backoff on reclaim, "session ended" only *after*
reclaim.

## What is NOT tested / known gaps (what breaks first in production)

- **Daemon restart while a session is live loses `session_state`.** It is in-memory.
  On restart, boot detection sees `session.pid` and the poller yields (IDLE +
  should_poll), so it behaves correctly — but when that session dies the daemon
  polls without the grace/notification RECLAIM sequence (no "session ended" ping).
  `check_stale_handoff` clears the marker; the *notification* on a
  restart-straddling session is a 1.8 / 2.3 concern. Not tested here.
- **`max_sessions` counts `engine.list_sessions()` alive at decision time** — a
  TOCTOU window exists between the cap check and `create_session`. With one human
  operator and a default cap of 3 this is theoretical; a hard cap enforced inside
  the engine is not implemented.
- **The startup-grace reclaim (never-alive launch) is reasoned + unit-tested with a
  fake clock, but not stress-tested against a real slow-booting claude.** 30s is a
  guess; a genuinely slow first-run (plugin install, model download) could trip it.
  Revisit alongside 1.6 login detection.
- **Flow expiry granularity is one poll cycle.** At the 50s production long-poll,
  an abandoned flow can live up to ~50s past `flow_timeout_s` before the expiry
  notice fires. Fine for a 5-min timeout; noted.
- **The real-abs.sh launcher test stubs `claude`/`curl`/`bun`.** It proves the flag
  parses, dies-on-unpaired, skips prompts, forwards `--away` → `acceptEdits`, and
  reaches `exec` — but a real `claude --channels` handshake (plugin polling, token
  handoff on the wire) is the human's headline demo, not automated (§10).
- **`abs config workspace-root` / `abs project` were exercised via the Python CLI
  and unit tests, but the bash shims (`cmd_project`, the cmd_config intercept) were
  shellcheck-clean, not run end-to-end here** (they `exec` into the tested Python).

## Deviations from PLAN.md

- **`daemon-handoff.json` gains a `chat_id` field** beyond the plan's
  timestamp/project/mode. Required so RECLAIM/stale-cleanup can address the "session
  ended" notice; it is local 0600 data and leaks no secret (the chat id is already
  in `rc.json`).
- **`--away` added as an `abs.sh` global flag** (not only the `ABS_AWAY` env var).
  It simply sets `ABS_AWAY=1`, reusing the existing mechanism; the plan's launcher
  contract (`--daemon-start [--away]`) needs the flag form.
- **Two config fields added** (`flow_timeout_s`, `session_start_grace_s`), validated
  and defaulted; `from_dict` already ignores unknowns so older/newer files coexist.
- **Rewrote two 1.3-era poller tests** whose assertions 1.5 supersedes: ABS START no
  longer pools (it launches the flow), and a stray callback is now answered-not-pooled
  (the 1.3 critique explicitly forecast this). No coverage lost; new behavior asserted.
- **`START_ACK` retained but effectively dead** (ABS START is intercepted before the
  pool path). Left as a public constant to avoid churning the module surface.
