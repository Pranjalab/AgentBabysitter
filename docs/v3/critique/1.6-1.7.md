# Critique — Steps 1.6 (login detection) + 1.7 (kill ladder while idle + pool forwarding)

## What was built

**1.6 — login detection.**
- *Pre-launch* (`Poller._credentials_present` + a precheck at the very start of
  `_do_handoff`, immediately before HANDOFF): the Claude Code credentials file
  (`$HOME/.claude/.credentials.json`, injectable for tests) must exist and be
  non-empty. Missing/empty → do NOT launch, send the predefined
  `LOGIN_MISSING_MSG`, emit `error {where:"login_precheck"}`, stay IDLE. The flow
  is already complete so nothing is left half-done; the pool is untouched (D14).
- *Post-launch*: the existing `failed_start` path (session never alive within
  `session_start_grace_s`) now sends `FAILED_START_MSG` ("session ended immediately
  — possible login issue…") instead of the generic "session ended". The
  `session_end` event's reason stays `failed_start`.
- *Version tolerance*: the signal is exit-timing (grace window) and file
  presence/size — never CLI output parsing (PLAN 1.6).

**1.7 — kill ladder while idle.** Three exact-whole-message, case-insensitive,
allowlist-gated, text-only commands (NO slash aliases / menu entries — deliberate
friction), each emitting a `command` event:
- `ABS OFF` → `Profile.set_off()` writes `dmPolicy:"disabled"` to **access.json**
  (the SAME field/file `abs.sh set_policy disabled` uses) → ack → `should_poll()`
  stops the poller. Recovery: terminal `abs on`.
- `ABS BLOCK` → `Profile.set_blocked()` writes `.blocked:true` to **rc.json**
  (mirrors `_hook_control`) → ack → poller stops. Recovery: terminal `abs setup`.
- `ABS CLEAR POOL` → `pool.clear()` → ack with the removed count.

**1.7 — pool forwarding.** Selection is a flow step before HANDOFF; selected
messages are delivered as claude's initial prompt (see the two corrections below).

## The two PLAN.md 1.7 corrections (plan author authorized; they override the plan)

**CORRECTION 1 — selection timing (was "on session start").** After HANDOFF the
in-session plugin owns the getUpdates token, so a user's reply to a "which to
send?" prompt would land in the *session*, not the daemon — the daemon would never
see the answer. **Fix:** pool selection is a FLOW step, *before* handoff. After the
mode screen (or a Resume tap), if `pool.unforwarded()` is non-empty, `_finalize_or_pool`
shows "📨 n pooled message(s) waiting" + numbered previews (truncate 60) + a
`[📤 Send all] [🙈 Skip]` keyboard (numbered-text `send 1,3` / `send all` / `skip`
too). Only when send/skip resolves does the handoff fire.

**CORRECTION 2 — delivery mechanism (was "re-send to the bot").** A bot never
receives its own `sendMessage` back via `getUpdates`, so "re-send so the plugin
delivers them" cannot work. **Fix:** selected texts are joined
(`"Messages received while you were offline:\n" + "\n".join(texts)`) and delivered
as claude's **initial prompt** — one argv element through the launcher:

```
["bash", "<abs.sh>", "--profile", "<p>", "--daemon-start",
 [--away], [--continue], "--prompt", "Messages received while you were offline:\n<m1>\n<m2>"]
```

The prompt is a single argv element (no shell rejoining), so quotes, newlines and
emoji survive: the tmux engine passes argv directly; herdr `shlex.join`s it (the
prompt token is shell-quoted as one unit). `abs.sh`'s `--prompt <value>` global
flag re-emits the value as claude's positional prompt in `exec claude … "$@"
<prompt>`. **Refinement I made to the brief's "positional passthrough":** I used a
`--prompt` *flag* rather than a *bare* trailing positional, because a bare positional
(`bash abs.sh … "text"`) is read by abs.sh's dispatch as an unknown *command* and
dies. The flag routes cleanly and lands at claude as the same positional prompt.

D14 discipline: `forwarded_at` is stamped on the selected messages ONLY after
`create_session` succeeds (in `_do_handoff`, post-SESSION_LIVE). A skip forwards
nothing; a failed launch or an expired selection screen marks nothing — those
messages stay unforwarded, kept in the pool.

## Gate — PLAN 1.6 "no credential contents ever read or logged", line by line

`_credentials_present` is the ONLY code that touches the credentials file:

```python
def _credentials_present(self) -> bool:
    try:
        return self.creds_path.stat().st_size > 0
    except OSError:
        return False
```

- `Path.stat()` performs an `lstat`/`stat` syscall — it returns metadata (size), it
  does **not** open the file or read a single byte. `st_size > 0` is the whole test.
- The file is never passed to `open()`, `read_text()`, `read_bytes()`, `json.load`,
  or any logger. `test_credentials_never_opened_for_read` monkeypatches
  `Path.open` / `read_text` / `read_bytes` to blow up if the creds path is the
  target and asserts the precheck still returns True — proving stat-only access.
- On failure the daemon logs only `"login precheck failed — not launching"` (no
  path contents) and emits `error {where:"login_precheck"}` — no path, no bytes.
- The predefined user message is a fixed string; it contains no file data.

Verified: no path anywhere reads or logs credential contents.

## Kill-ladder state-file writes (which file/field)

| Command | File | Field written | Preserves | Recovery |
|---|---|---|---|---|
| ABS OFF | `<tg_dir>/access.json` | `dmPolicy = "disabled"` | allowFrom, groups, ackReaction, … | terminal `abs on` |
| ABS BLOCK | `<profile>/rc.json` | `blocked = true` | tg_dir, bot, quiet, … | terminal `abs setup` |
| ABS CLEAR POOL | `<profile>/pool.jsonl` | (removed) | — | — |

Both writes are atomic (temp + `os.replace`, 0600) and MERGE (read → update one
field → write), so no other key is dropped. Proven by
`test_set_off_writes_disabled_preserves_keys` / `test_set_blocked_...`.

## Honest gaps / what breaks first

- **The interactive-prompt-arg assumption is unverified in automation.** We assert
  the launcher argv shape and that abs.sh forwards `--prompt` to claude as a
  positional (`test_daemon_start_prompt_forwarded_to_claude` with a stub claude),
  but we never run real `claude [--continue] "prompt"` (no real claude in tests).
  Whether interactive `claude` treats a positional as the opening user turn — and
  whether it composes with `--continue` — is confirmed only by the human's live
  test. Documented in the manual test as the thing to watch.
- **The daemon now WRITES two profile state files** (access.json, rc.json) — a
  departure from the "Profile is read-only; only the CLI writes" discipline of 1.3.
  This is D11-sanctioned (the kill ladder extends to the daemon) and touches only
  the off/blocked flags, never the allowlist (5.3). Still, it is the daemon's first
  write into `abs.sh`'s files; a format drift there would now affect two writers.
- **Pooled content appears in the launched process's argv** (`--prompt <text>`),
  visible via `ps`/`/proc/<pid>/cmdline` to same-user processes. It is the user's
  own messages on the user's own machine (same trust boundary as the pool file),
  but it is *more* visible than the 0600 pool file. A file-based hand-off would be
  more private; the brief chose argv. Noted.
- **herdr's shell-retype of a newline-containing prompt** (`shlex.join` → typed into
  the pane shell) is asserted only at the argv layer, not end-to-end through herdr
  (no real claude). A pathological prompt could in theory mis-parse on the herdr
  retype; the tmux path (direct argv, no shell) is unaffected. Live test covers it.
- **`ABS OFF`/`BLOCK` take effect on the NEXT `should_poll()`**, i.e. the current
  batch finishes first (the ack is sent, then the poller yields next cycle). No
  in-flight message is mishandled, but there is a one-cycle window — matches the
  terminal `set_policy` "no restart needed, picks up on next message" behavior.
- **Login precheck is presence+size, not validity.** A present-but-corrupt or
  expired credentials file passes the precheck; the post-launch `failed_start`
  path is the backstop (session dies fast → login-issue note). Full validity is out
  of scope (never parse credentials).

## Deviations from PLAN.md

- The two 1.7 corrections above (authorized by the plan author).
- `--prompt` flag vs bare positional (rationale above); documented in
  `flow.build_launcher_argv`.
- `Profile.set_off` / `set_blocked` added — the daemon's only writes to profile
