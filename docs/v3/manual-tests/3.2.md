# Manual test — Step 3.2: sandbox as a session target

Prereq: Docker; the daemon installed + running; a paired `default` profile. This
runs a REAL Claude Code session inside a container, driven from your phone.

> One-time: 3.2 needs the **v2** image (adds bun for the plugin + the launcher).
> `abs sandbox build --rebuild`, then re-create any old sandboxes.

## 1. Create a sandbox (if you don't have one)

```sh
abs sandbox build            # v2 (bun + absd-session), ~1GB first time
abs sandbox create demo --ports 3000:3000
```

## 2. ABS START → 🏖 Sandbox (from the phone)

With no session running, send **`ABS START`** →

- On the project screen there's a **"🏖 Sandbox…"** entry → tap it.
- A sandbox sub-picker lists your sandboxes (running/stopped) + **"➕ New sandbox"**.
  Pick **demo** (or create one — it asks a validated name).
- Pick **🟢 Normal**.

Expected: the daemon starts the container (if stopped) and launches Claude Code
**inside** it; the confirmation gives `abs attach default`.

## 3. Message it — it's real claude, in the box

Send the session a task from Telegram, e.g. *"clone https://github.com/octocat/Hello-World
and tell me what's in it, then serve the folder on port 3000."* It should:
- reply over Telegram (the plugin polls from **inside** the container),
- `git clone` (the box has net + git),
- serve on :3000 → open **http://localhost:3000** on your host (the published port).

The work lands in the sandbox's dedicated host folder (`~/Projects/sandboxes/demo`),
synced live.

## 4. Attach at the desk

```sh
abs sessions           # shows the live session
abs attach default     # drops you into the in-container claude TUI
```

Detach (tmux `Ctrl-b d` / herdr `Ctrl-b q`) → the container AND the session keep
running. `abs attach` again returns you.

## 5. End the session — the sandbox survives

End the session (exit claude in the attached view, or `ABS EXIT` from Telegram —
note: in a sandbox this reaches claude but isn't hook-enforced, so exiting in the
attached session is the reliable way for now). Within ~10 s the bot answers as the
daemon again ("⏹ Session ended").

```sh
abs sandbox list       # 'demo' is STILL THERE (stopped) — the container survived
```

Start another session in the same sandbox any time (`ABS START` → 🏖 Sandbox → demo,
or `abs start sandbox demo` at the terminal). Destroy it when done:

```sh
abs sandbox destroy demo          # removes the container; KEEPS the host folder
abs sandbox destroy demo --purge  # also removes ~/Projects/sandboxes/demo
```

## Terminal path

`abs start sandbox [name]` runs a sandbox session directly in your terminal (picker
if you have several). The daemon yields while it's live and reclaims when you exit.

## Security note (read once)

A sandbox session for the SAME bot has a COPY of your whole `~/.claude` inside —
including the bot token. That's fine for your own work; for anything untrusted, use
a dedicated bot/credentials per sandbox (a later stage will make that a first-class
option). The container itself is isolated (non-root, no privileged, one bind mount).
