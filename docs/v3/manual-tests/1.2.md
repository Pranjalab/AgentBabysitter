# Manual test — Step 1.2: HerdrEngine + `abs sessions` / `abs attach` through herdr

Run from the repo root (`~/Projects/research/AgentBabysitter`) on branch `v3-daemon`.
This is the Step 1.1 flow (create headless → `abs sessions` → attach → scroll →
detach → survives → cleanup) but on the **herdr** engine, so you also *feel*
herdr's UI (the deferred UI evaluation, now on ABS's own session). It uses a
throwaway herdr session named `abs-demo`. Nothing here touches your real profiles,
`~/.abs`, `~/.claude`, real bots, or the herdr `default` session.

Requires herdr (you have 0.7.5 at `~/.local/bin/herdr`). `~/.local/bin` must be on
PATH (`herdr --version` → `herdr 0.7.5`). The `ABS_ENGINE=herdr` prefix on the
`abs` commands tells the session adapter to use herdr instead of tmux — it passes
straight through the `abs.sh` shim, no config change needed.

## 2. No sessions yet

```bash
ABS_ENGINE=herdr bash abs.sh sessions
```

Expect: `No ABS sessions.` (exit 0).

## 3. Create a demo session (one-liner, through the real herdr engine)

This starts a **headless** herdr server + workspace for `abs-demo` in the current
directory and runs an interactive shell in its pane — nothing attaches, exactly
the daemon's code path.

```bash
.venv/bin/python -c "from pathlib import Path; from absd.engines.herdr import HerdrEngine; HerdrEngine().create_session('demo', Path.cwd(), ['bash'], {})"
```

Expect: no output, exit 0. (Runs headless — it does NOT drop you into the session.)

## 4. `abs sessions` shows it

```bash
ABS_ENGINE=herdr bash abs.sh sessions
```

Expect a table like:

```
PROFILE  ALIVE  CWD
demo     yes    /home/pranjal/Projects/research/AgentBabysitter
```

And the JSON form for scripts:

```bash
ABS_ENGINE=herdr bash abs.sh sessions --json
```

Expect a one-element JSON array with `"profile": "demo"`, `"alive": true`, and the
cwd.

## 5. Attach — this is the herdr UI evaluation

`abs attach` execs the herdr attach command for you (it needs a real terminal —
you're in one):

```bash
ABS_ENGINE=herdr bash abs.sh attach demo
```

You should land **inside** the herdr UI with the `abs-demo` pane (a shell prompt)
already running — it was started headless; you just joined it. Now check the feel:

1. In the pane, produce a screenful of scrollback, e.g. `seq 1 500`.
2. **Scroll up with your mouse wheel / trackpad.** Does it scroll the way you
   wanted and tmux never did?
3. **The sidebar** — the workspace/pane sidebar is visible on the side (labelled
   `abs-demo`). This is where "which project needs me" will live in the always-on
   vision — is it readable?

> `abs attach` with no argument also works here (single live session), landing in
> the same place. The exact command it runs is `herdr session attach abs-demo`.

## 6. Detach — the session keeps running

Detach with **`Ctrl-b`** then **`q`** (herdr's detach). You drop back to your
normal shell; the session is NOT killed.

```bash
ABS_ENGINE=herdr bash abs.sh sessions
```

Expect: the `demo` row is still there, `ALIVE yes` — detach left it running.

## 7. Cleanup

```bash
.venv/bin/python -c "from absd.engines.herdr import HerdrEngine; HerdrEngine().kill('demo')"
ABS_ENGINE=herdr bash abs.sh sessions
```

Expect: `No ABS sessions.` — the demo session is stopped and deleted.

Belt-and-suspenders (should all show nothing ABS-related):

```bash
herdr session list --json | python3 -c "import json,sys; print([s['name'] for s in json.load(sys.stdin)['sessions'] if s['name']!='default'] or '(only default — clean)')"
pgrep -x herdr && echo "!! herdr server still running" || echo "(no herdr server — clean)"
```

Expect: `(only default — clean)` and `(no herdr server — clean)`.
