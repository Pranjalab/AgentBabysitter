# Manual test — Step 0.2: herdr UI evaluation + attach/detach/events

This is your deferred **UI evaluation** and the human half of the go/no-go gate.
Budget ~10 minutes. It does two things the automated `herdr_spike.sh` cannot:
let you *feel* the UI (mouse, scrolling — your main tmux complaint) and watch a
real agent-status change land in the sidebar.

Prereq: herdr 0.7.5 is installed at `~/.local/bin/herdr` (Step 0.2 did this).
Everything below uses a throwaway named session `abs-spike`. Nothing touches
`~/.abs`, real bots, or your normal claude sessions.

All commands assume `~/.local/bin` is on your PATH (`herdr --version` → `herdr 0.7.5`).

---

## Part A — headless start, then attach (the core promise)

Goal: prove a session that was started with **nothing attached** can be walked
up to and attached from the terminal.

1. Start a headless server for `abs-spike` (this is what the daemon will do — no
   window opens):

   ```bash
   HERDR_SESSION=abs-spike nohup herdr server >/tmp/abs-spike.log 2>&1 &
   ```

2. Create a workspace in a scratch dir and run something long-lived in it,
   without ever attaching:

   ```bash
   mkdir -p /tmp/abs-spike-ws
   HERDR_SESSION=abs-spike herdr workspace create --cwd /tmp/abs-spike-ws --label abs-spike --no-focus
   HERDR_SESSION=abs-spike herdr pane run w1:p1 "htop"
   ```

3. Confirm it is live from the outside (still nothing attached):

   ```bash
   HERDR_SESSION=abs-spike herdr session list --json   # abs-spike -> "running":true
   HERDR_SESSION=abs-spike herdr pane list              # one pane, w1:p1
   ```

4. **Now attach** — this is the "walk to the desk" moment:

   ```bash
   HERDR_SESSION=abs-spike herdr
   ```

   Expect: the full herdr UI opens with your `htop` pane already running. It was
   started headless; you just joined it.

---

## Part B — the UI evaluation (this is the point)

Do these inside the attached UI. **This is your judgment call**, not a pass/fail:

- [ ] **Mouse scroll** — scroll the mouse wheel over the `htop` pane. Does the
      scrollback scroll the way you wanted and tmux never did?
- [ ] **Click to focus** — split a pane (right-click → split, or `ctrl+b v`) and
      click between panes. Does click-to-focus feel right?
- [ ] **Drag to resize** — drag the border between two panes.
- [ ] **Drag-select to copy** — drag-select some text; it copies without `ctrl+c`.
      Double-click a token to copy it.
- [ ] **The sidebar** — is the workspace/agent sidebar readable? This is where
      "which project needs me" lives in the always-on vision.

Jot a one-line verdict: does the UI clear the bar, or should `auto` default to
tmux? (Either answer is fine — D4 means the plan proceeds regardless; only the
default engine changes.)

---

## Part C — detach, prove it keeps running, reattach

1. **Detach** with `ctrl+b q` (or just close the terminal window). The server and
   `htop` keep running.
2. From a plain shell, confirm it survived:

   ```bash
   HERDR_SESSION=abs-spike herdr session list --json   # still "running":true
   ```
3. **Reattach**: `HERDR_SESSION=abs-spike herdr` — same `htop`, still going.
4. Detach again (`ctrl+b q`).

---

## Part D — watch a real agent status change (the herdr-only superpower)

This is what tmux can never do and what Phase 2.1 (blocked-session pings) is
built on. You will run the real `claude` in a pane and watch the status flip.

1. Open a **second** terminal and start a live status watcher on the pane:

   ```bash
   herdr agent list                       # note: no agent yet
   # in a loop, watch the status field:
   watch -n1 'HERDR_SESSION=abs-spike ~/.local/bin/herdr agent get w1:p1 2>/dev/null | \
     python3 -c "import json,sys;a=json.load(sys.stdin)[\"result\"][\"agent\"];print(a[\"agent\"],a[\"agent_status\"])"'
   ```

   (If you prefer, attach the full UI instead and watch the sidebar dot.)

2. In your first terminal, launch real claude in the pane:

   ```bash
   HERDR_SESSION=abs-spike herdr pane run w1:p1 "claude"
   ```

   Within a few seconds the watcher shows `claude idle` — herdr auto-detected it,
   no integration install needed.

3. Give it a quick task and watch `idle → working → idle`:

   ```bash
   HERDR_SESSION=abs-spike herdr agent prompt w1:p1 "Reply with just the word: pong"
   ```

4. **See a `blocked` state** (the one the spike could NOT capture automatically,
   because this machine auto-approves trivial commands). To force a real approval
   prompt, ask claude to do something it must ask about in Normal mode — e.g.
   attach the UI (`HERDR_SESSION=abs-spike herdr`), watch the pane, and prompt it
   to run a command it isn't pre-allowed to run. When claude shows its
   approval/permission prompt, the sidebar/agent status should flip to `blocked`.
   **Just observe it — do not approve or deny for this test.** Confirm you saw
   `blocked` arrive, then move on to cleanup. (This is the signal Phase 2.1 will
   turn into a Telegram "waiting for you" ping.)

   Note: herdr's blocked detection is strict — an unusual prompt may read `idle`
   for a moment before it flips to `blocked`. That latency is expected.

## Cleanup (do this when done)

```bash
HERDR_SESSION=abs-spike herdr session stop abs-spike     # kills panes + server
HERDR_SESSION=abs-spike herdr session delete abs-spike   # removes saved state
pgrep -af 'herdr|htop' | grep abs-spike                  # expect: nothing
rm -rf /tmp/abs-spike-ws /tmp/abs-spike.log              # scratch, safe to remove
```

Verify nothing lingers:

```bash
herdr session list --json    # abs-spike should be gone; only "default"
pgrep -a herdr               # expect: no output
```
