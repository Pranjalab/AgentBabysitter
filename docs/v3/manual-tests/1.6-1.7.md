Your setup: one profile `default`, daemon installed. Reload it so the new code is
live: `abs daemon install && systemctl --user restart absd`.

## 1. Pool forwarding (the headline)

You already have **2 pooled messages** from this morning (sent while no session was
running). Verify they get offered and delivered:

1. Make sure no session is live, then confirm the pool:

   ```
   abs status          # the v3 block should show pool=2 for default (or: send ABS POOL)
   ```

2. From the phone: **`ABS START`** → pick a project (or ▶ Resume) → **Normal**.

3. Expected next screen (before it launches):

   ```
   📨 2 pooled message(s) waiting:
   1. <preview of message 1>
   2. <preview of message 2>

   Tap 📤 Send all / 🙈 Skip — or reply `send all`, `send 1,3`, or `skip`.
   ```

4. Tap **📤 Send all** → the session starts, and its **first turn** is the two
   messages (prefixed "Messages received while you were offline:"). Confirm claude
   responds to them. *(This is the one thing to eyeball: that interactive claude
   treats the forwarded prompt as its opening message — if it starts blank instead,
   tell me; the automated tests assert the argv shape but not real claude's
   handling of a positional prompt.)*

5. `ABS POOL` (or `abs status`) now shows those messages as forwarded (kept, not
   deleted — D14). Choosing **🙈 Skip** in step 4 would keep them unforwarded for
   next time; replying `send 1` forwards only the first.

## 2. Login detection (1.6)

Temporarily hide your credentials to prove the precheck (RESTORE right after):

6. At the terminal:

   ```
   mv ~/.claude/.credentials.json ~/.claude/.credentials.json.bak
   ```

7. From the phone: **`ABS START`** → pick a project → **Normal**.

   Expected: **"⚠ Claude Code is not logged in on this machine. Please run `claude`
   in a terminal and complete login, then try ABS START again."** — and **nothing
   launches** (`abs sessions` shows none; `abs daemon logs` shows an
   `error … login_precheck`).

8. **Restore immediately:**

   ```
   mv ~/.claude/.credentials.json.bak ~/.claude/.credentials.json
   ```

   Then `ABS START` again → it launches normally.

*(The post-launch backstop — a session that dies within ~30 s → "⚠ Session ended
immediately — possible login issue" — is harder to trigger by hand; the pre-launch
check above is the main one.)*

## 3. Kill ladder while idle (1.7)

9. **ABS CLEAR POOL** (only after step 1, or it clears real pooled messages) — from
   the phone, send **`ABS CLEAR POOL`** → expect **"🗑 Pool cleared (n message(s)
   removed)."**; `abs status` shows pool=0.

10. **ABS OFF** — send **`ABS OFF`** → expect **"📴 Inbound off. Re-enable from the
    terminal: abs on"**. Now send any message → **silence** (the bot is deaf; the
    daemon stopped polling). Confirm `abs status` shows `default: off`.

11. Re-enable at the terminal:

    ```
    abs --profile default on
    ```

    Send a message again → you get the pool ack (daemon polling again).

12. **ABS BLOCK** (optional — heavier) — send **`ABS BLOCK`** → expect the block
    ack; the bot goes deaf and `abs on` **refuses** (says it's blocked). Recover
    only with `abs --profile default setup`. *(Skip unless you want to re-run
    setup.)*

## What this does NOT cover

- Real-claude handling of the forwarded positional prompt (step 4 eyeball).
- Credential *validity* — the precheck is presence+size only; an expired token
  passes here and is caught post-launch by the fast-death backstop.
