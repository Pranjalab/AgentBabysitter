# Manual test — Step 3.1: Docker sandbox lifecycle

Prereq: Docker installed and your user in the `docker` group; a repo checkout with
`.venv`. This proves the sandbox is a real, working, isolated box — and that
nothing outside its dedicated folder is touched.

## 1. Build + create

```sh
abs sandbox build                         # ~1GB first time; cached after
abs sandbox create test1 --ports 3000:3000
```

Expected: `create` prints the workdir (`~/Projects/sandboxes/test1`), the published
port, and the **credential-copy tradeoff warning**. `abs sandbox list` shows `test1`
(stopped).

## 2. Shell in — logged-in claude, git, a page on :3000

```sh
abs sandbox start test1
docker exec -it absd-sbx-test1 bash       # you're 'dev' in /home/dev/workspace
```

Inside the container:

```sh
whoami                                    # dev (non-root)
claude --version                          # Claude Code is installed
ls -la ~/.claude/.credentials.json        # your credentials were copied in
git clone https://github.com/octocat/Hello-World   # net works (default bridge)
python3 -m http.server 3000               # serve on the published port
```

From your **host browser**, open <http://localhost:3000> → you see the directory
listing served from inside the sandbox (the workdir is bind-mounted, so files you
create at `~/Projects/sandboxes/test1` on the host appear here live, and vice versa).

## 3. Isolation spot-check

- On the **host**, create a file: `echo hi > ~/Projects/sandboxes/test1/host_note.txt`
  → inside the container `cat ~/workspace/host_note.txt` shows it (live sync).
- Inside the container, try to reach the rest of your host — you can't: only
  `/home/dev/workspace` is mounted. `ls /` shows a clean container root, not your home.
- Edit the copied credentials inside (`echo x >> ~/.claude/.credentials.json`) →
  your **host** `~/.claude/.credentials.json` is unchanged (it's a copy, not a mount).

## 4. Destroy — and confirm nothing else was touched

```sh
exit                                      # leave the container shell
abs sandbox destroy test1                 # removes the container; KEEPS the folder
ls ~/Projects/sandboxes/test1             # your work is still here (user data)
abs sandbox destroy test1 --purge         # (optional) also delete the folder
```

Expected: `destroy` (no `--purge`) removes the container but tells you the host
folder is kept and how to remove it. Your host filesystem **outside**
`~/Projects/sandboxes/test1` is untouched throughout — nothing in `$HOME`, no other
project, and `~/.claude` in particular is byte-for-byte as it was.

## Security posture (what to expect)

`docker inspect absd-sbx-test1` (before destroy) shows `Privileged=false`,
`Config.User=dev`, and `HostConfig.Binds` is exactly the one workdir. No
`--privileged`, no docker socket, no other host mount. The only host secret inside
is the credential copy — for real isolation, use a dedicated bot/credentials per
sandbox (see Step 3.2 when it lands).
