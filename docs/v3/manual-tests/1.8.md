# Manual test — Step 1.8: Phase-1 final acceptance (end-to-end)

One run that touches everything Phase 1 shipped. Your setup: one profile `default`,
a repo checkout with `.venv`. ~20 minutes. Nothing here needs a second bot.

## 0. Install refresh + doctor

```sh
./install.sh                 # accept the daemon refresh when asked; herdr optional
# or, directly:
abs daemon install && systemctl --user restart absd
abs doctor
```

Expected: `abs doctor` shows all ✓ for Core, Daemon (installed/enabled/active +
linger), Python & engines (absd importable, tmux and/or herdr with versions),
Config & state (config valid, files 0600, no errors).

## 1. Restart survival (reboot-sim)

1. From the phone: **`ABS START`** → pick a project → **Normal**. Give the session
   a small task so it's clearly alive. Note the confirmation's `abs attach default`.
2. **Simulate a daemon restart** (the real reboot notice path):

   ```sh
   systemctl --user restart absd
   abs daemon status
   ```

   Expected: the daemon comes back and — because your session was still alive —
   `abs daemon status` shows `default: yielding-to-session` with the live session
   (engine, project, age, attach). **You get NO "did not survive" message** (it
   survived). `tail ~/.abs/daemon/events.jsonl` shows a fresh `daemon_start` but no
   new `session_end`.

3. Now end the session at the desk in a way that does NOT go through the daemon:
   `abs attach default`, then `Ctrl-c`/exit inside it (or `ABS EXIT` from the
   phone). Within ~10 s you get **"⏹ Session ended…"** and the bot listens again.

## 2. Pool + forwarding

4. With nothing running, send the bot **2 or 3 plain messages** (they get the pool
   ack). Then **`ABS START`** → project → **Normal** → the **pool-selection** screen
   appears ("📨 n pooled message(s) waiting…"). Tap **📤 Send all**.
5. Expected: the session starts and its **first turn is those messages**. Confirm
   Claude responds to them. `ABS POOL` shows them kept (forwarded, not deleted).

## 3. Attach + menu

6. `abs sessions` lists the live session (ENGINE column). `abs attach default`
   drops you in; detach without killing it.
7. In Telegram, open the **"/"** menu: while the session is live it shows
   `/abs_exit` + `/usage`; end the session → it returns to `/abs_start /abs_status
   /abs_pool`.

## 4. Kill ladder + dashboard + trail

8. **`ABS OFF`** → "📴 Inbound off…"; send anything → silence. `abs status` shows
   `default: off`. Re-enable at the terminal: `abs --profile default on` → the bot
   listens again.
9. **`abs status`** — the full picture: the daemon header (running, version,
   uptime), and the `default` line with state / live session / pool / recent
   projects.
10. The machine trail:

    ```sh
    tail -20 ~/.abs/daemon/events.jsonl
    # session lifecycle only:
    jq -rc 'select(.event=="handoff" or .event=="session_start" or .event=="session_end")' \
      ~/.abs/daemon/events.jsonl
    ```

    Expected: one JSON object per line — `daemon_start`, `command`, `handoff`,
    `session_start`, `poller_state`, `session_end`, `reclaim_done`, `menu_set`, …
    with **no message text** anywhere (`message_pooled` carries only `update_id`).

## 5. Login detection (optional, rename/restore)

11. `mv ~/.claude/.credentials.json ~/.claude/.credentials.json.bak` → `ABS START`
    → **"⚠ Claude Code is not logged in…"**, nothing launches. **Restore:**
    `mv ~/.claude/.credentials.json.bak ~/.claude/.credentials.json`.

## What this does NOT cover

- Real reboot (as opposed to `systemctl --user restart absd`): the recovery path is
  the same, but a true reboot also exercises linger — spot-check once if you like.
- Three bots at once (G5): the machinery is per-profile; verify one at a time.
- Real-claude handling of the forwarded positional prompt (step 5 eyeball).
