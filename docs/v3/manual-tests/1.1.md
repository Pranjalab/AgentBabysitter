# Manual test — Step 1.1: Engine adapter (TmuxEngine) + `abs sessions` / `abs attach`

Run from the repo root (`~/Projects/research/AgentBabysitter`) on branch `v3-daemon`.
These use ABS's **isolated tmux socket** (`-L abs`) and a throwaway session named
`abs-demo`. Nothing here touches your real profiles, `~/.abs`, `~/.claude`, or any tmux
server you started yourself. Each step gives the exact command and what to expect.

Requires tmux (you have 3.4). If you use tmux elsewhere, note this runs on a *separate*
socket — your normal `tmux` sessions are invisible here and unaffected.

## 1. Automated tests for this step pass

```bash
.venv/bin/python -m pytest tests/test_engine_tmux.py
```

Expect: `18 passed`, exit 0.

> A bare `.venv/bin/python -m pytest` runs the whole suite (49 as of this step, and it
> grows with later steps). Scope to this file so the expected count stays stable.

## 2. No sessions yet

```bash
bash abs.sh sessions
```

Expect: `No ABS sessions.` (exit 0).

```bash
bash abs.sh attach
```

Expect: `No live ABS sessions. Start one with ABS START from Telegram, or run `abs` at
the terminal.` and exit 1.

## 3. Create a demo session (one-liner, through the real engine)

This launches an interactive shell inside an ABS-managed tmux session `abs-demo`, on the
tuned config, in the current directory — the same code path the daemon will use.

```bash
.venv/bin/python -c "from pathlib import Path; from absd.engines.tmux import TmuxEngine; TmuxEngine().create_session('demo', Path.cwd(), ['bash'], {})"
```

Expect: no output, exit 0. (Runs headless — it does NOT drop you into the session.)

## 4. `abs sessions` shows it

```bash
bash abs.sh sessions
```

Expect a table like:

```
PROFILE  ALIVE  CWD
demo     yes    /home/pranjal/Projects/research/AgentBabysitter
```

And the JSON form for scripts:

```bash
bash abs.sh sessions --json
```

Expect a one-element JSON array with `"profile": "demo"`, `"alive": true`, and the cwd.

## 5. `abs attach` drops you in — this is the tuned-conf feel test

```bash
bash abs.sh attach demo
```

You should land **directly inside** the session (a shell prompt). Now check the tuned
config feels right:

1. Run something that produces a screenful of scrollback, e.g. `seq 1 500`.
2. **Scroll up with your mouse wheel / trackpad.** It should scroll the tmux scrollback
   smoothly (that's `mouse on` + `history-limit 50000`). Press `q` to leave copy-mode.
3. Note the minimal status bar at the bottom: `abs:demo` on the left, a clock on the
   right — no window-list clutter.

> `abs attach` with no argument would also work here (single live session), landing in
> the same place. With several live sessions it asks you to name one.

## 6. Detach — the session keeps running

Use the standard tmux detach: press **`Ctrl-b`** then **`d`**.

Expect: you drop back to your normal shell; the session is NOT killed.

```bash
bash abs.sh sessions
```

Expect: the `demo` row is still there, `ALIVE yes` — detach left it running.

## 7. Cleanup

```bash
.venv/bin/python -c "from absd.engines.tmux import TmuxEngine; TmuxEngine().kill('demo')"
bash abs.sh sessions
```

Expect: `No ABS sessions.` — the demo session is gone.

Optional belt-and-suspenders (should show nothing ABS-related on the isolated socket):

```bash
tmux -L abs list-sessions 2>&1 || echo "(no server — clean)"
```

Expect: either an empty list or `no server running` / `(no server — clean)`.
